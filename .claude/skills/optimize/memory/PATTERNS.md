### [2026-09-09] — Optimize — Profiler MCP tools are non-functional in this project's unity-mcp session
**Context:** First `/optimize` run — attempted Pass 2 (runtime performance) using `Unity_Profiler_*` tools against a live, genuinely-ticking Play Mode session (`Time.frameCount` climbing normally, 2900+ frames).
**Learning:** Every `Unity_Profiler_*` tool (`GetOverallGcAllocation`, `GetFrameRangeGcAllocation`, `GetFrameRangeTopTimeSummary`, `GetFrameGcAllocation`, `GetFrameSelfTimeSample`, `GetFrameTopTimeSample`) failed with a generic "Exception has been thrown by the target of an invocation" error, even after explicitly enabling `ProfilerDriver.enabled`/`Profiler.enabled` via `RunCommand` and confirming real frames were captured (`ProfilerDriver.lastFrameIndex` reached 612). `ProfilerArea`/`ProfilerDriver.GetAreaEnabled` aren't accessible from a compiled `RunCommand` script either (internal API), so per-area enabling couldn't be attempted as a further diagnostic. This is a new entry in the project's running list of `unity-mcp` limitations (alongside reflection-in-`RunCommand`, blocked `AssetDatabase.DeleteAsset`, and the frozen-player-loop quirk already in `CLAUDE.md`).
**Apply when:** Any future `/optimize` Pass 2 attempt — don't assume the profiler tools work just because `unity-mcp` itself is connected and Play Mode is genuinely ticking; verify with a cheap single-frame call first before planning a full runtime pass, and skip Pass 2 explicitly (per the skill's own error-handling discipline) rather than retrying extensively if it fails the same way again. If someone resolves this (e.g. a package update, a different capture-start sequence), record the fix here.
